About

About me

I started my career writing Selenium and Java automation and testing REST and SOAP APIs. That work taught me to think about data flows, edge cases and regression risk, and that habit carries straight over to AI testing.

At Mohawk Industries I grew from enterprise testing on SAP C4C, Salesforce and SAP Commerce into leading QA for GenAI and LLM applications. Today I define the AI test strategy, test prompts and responses, validate RAG retrieval and grounding, and check that AI agents pick the right tools and recover from failures.

AI output is not deterministic, so I test for quality, not exact text. I look at accuracy, groundedness, context use, instruction following and business rules, and I compare results across prompt, model and knowledge base changes before anything goes to production.

AI Testing

How I test AI applications

LLM & Prompt Testing

Prompt test sets covering normal, negative, ambiguous and edge-case inputs.

  • Accuracy, relevance and completeness
  • Instruction following and response format
  • Hallucination and out-of-scope handling

RAG Validation

Checks that answers come from the right documents and say only what the sources support.

  • Document ingestion and retrieved chunks
  • Context relevance and source grounding
  • Citation accuracy and conflicting sources

Agentic AI Testing

Multi-step agent workflows tested from the first tool call to the final answer.

  • Tool selection and API invocation
  • State, context retention and handoffs
  • Timeouts, retries and incomplete runs

AI Regression

Quality compared across releases using defined criteria instead of exact-text matching.

  • Prompt and model changes
  • Configuration and retrieval changes
  • Knowledge base updates

AI API & Integration

AI services tested as part of the wider enterprise system they feed.

  • Request and response payloads
  • JSON structure and error handling
  • Data flow into connected systems

Test strategy, planning and release decisions for AI projects.
